# Web学習環境管理

## 起動

Docker Desktopを起動し、LLMonフォルダで実行します。

```bash
git pull --ff-only
bash scripts/Start-Web.sh
```

http://localhost:18083 を開きます。以前のRAGと同じポートを統合Web画面に変更しています。
既存RAGの文書索引・確認済みデータは維持されます。
`Start-RAG.sh`でも統合Web画面を起動できます。`Start-Docker.sh`はJupyterLabも起動します。
WebからDocker自体の起動・停止は行いません。DockerソケットやMacのシェルを公開していません。

## 画面構成

| 画面 | 機能 |
|---|---|
| 環境概要 | 登録数・ジョブ・成果物、コンテナCPU情報、ディスク空き、モデルキャッシュ状態 |
| 学習データ | 付属例の登録、train/valid/testアップロード、検証、版別保存、先頭例の確認・取得 |
| 学習設定 | モデル・更新回数・系列長・学習率・LoRA設定・CPUスレッド数の版別保存 |
| 学習ジョブ・ログ | バックグラウンド学習、停止要求、状態、更新ステップ、損失、末尾ログ |
| 成果物・回答比較 | アダプターZIP、設定・評価、学習前後の応答比較、PyTorch LoRAのRAG適用・解除 |
| 専門文書RAG | 既存の文書登録・検索・回答・人による学習候補確認 |

## 最初の学習試行

1. 学習データで「付属サンプルを登録」を押します。
2. 学習設定で「初期設定（短い例文用）」を選び、新しい設定名で保存します。
3. 学習ジョブでデータセットと設定を選び、確認チェックを入れて「LoRA学習を開始」を押します。
4. 「状態を更新」を押して実行ログ・進捗を確認します。
5. 状態が「完了」になったら、成果物でアダプターとtest評価結果を確認します。
6. 未学習の質問を入力し、学習前／学習後の回答比較を開始します。
7. ジョブの完了後に成果物画面を更新し、比較結果を原文・望む文体と照合します。

初回のモデル取得・トークン化・初期化中は進捗ステップが出ません。失敗時はログと終了コードを確認します。
画面の更新は手動です。損失・学習率などはTrainerのログ時に反映されます。
CPUでの初期値は0.6B・20ステップ・系列長256・バッチ1です。
1.7B・長い系列ではメモリ不足や長時間処理の可能性があります。

## データと設定の保護

登録データは`data/private/manager/datasets/<ID>/`に保存します。
各JSONLはUTF-8、空でない10MB以下とし、質問の重複や同じ元文書が分割をまたぐ状態を拒否します。
確認済みRAG学習候補は、元文書単位でtrain/valid/testを分割してからアップロードしてください。
文書が1つしかない場合、独立した評価文書を用意するまではRAGのみの試行を推奨します。

同じ名前でも新しいデータ版・設定版を追加し、以前の版を上書きしません。
開始時には`outputs/jobs/<ID>/data`と`config.json`に入力のコピーを保存します。
登録後に原本ファイルを直接変更した場合はハッシュ検査で拒否します。変更は新しい版として登録してください。
Web設定は登録されたモデルと数値範囲に限定し、任意コマンド実行には対応しません。

## ジョブの開始・停止と制限

ブラウザを閉じてもバックグラウンドワーカーが学習を続けます。
DockerコンテナやMacを停止すると学習は中断します。再起動後にワーカー消失を検出し、「中断」と表示します。
プロセス識別はLinuxのPID・起動時刻・boot IDを使用し、別プロセスを停止するようなPID直接操作はUIにありません。
状態が「開始待ち」のままワーカーが起動しなかった場合も、30秒経過後の更新時に中断を検出します。

同時ジョブは1件です。学習前後の比較も同じ枠を使います。
開始時にはキャッシュ済みRAGモデルを解放し、ジョブ実行中はRAG画面を休止してメモリ負荷を抑えます。
複数ブラウザやCLIからのモデル実行は別管理です。CLI学習やMLX学習を重ねて実行しないでください。

停止チェックを入れて「停止を要求」を押すと、ワーカーが子プロセスを終了します。
停止要求から表示更新まで数秒かかることがあります。停止時に新しいアダプターを必ず保存するわけではありません。
作成済みログ・チェックポイントは残しますが、自動再開・Webからの途中再開は未実装です。

## 成果物

- PyTorch学習成果物: `outputs/cpu/<ID>/`
- ジョブログ・入力コピー・回答比較: `outputs/jobs/<ID>/`
- 管理DB・データセット・設定: `data/private/manager/`

アダプターZIPは100MB以下に限定し、アダプター、トークナイザー、run.json、評価結果を含めます。
ベースモデル本体は含みません。途中/失敗の成果物は評価結果の欠落を警告します。
停止・失敗の成果物を正常な最終モデルとして扱わないでください。

RAGへの適用は、初期Qwen3 0.6BのPyTorchアダプターで評価結果がある場合に利用できます。
同じベースモデルであることを確認し、適用チェックを入れて押します。
上書き設定は`data/private/manager/rag-override.json`へ保存し、GitHub管理のconfig/rag.jsonは変更しません。
LoRA解除も成果物画面で行えます。解除しても成果物自体は残ります。

## MLX・GPUについて

M4 GPUのMLXはMacネイティブ環境です。このDocker内Web画面からの開始・停止は未対応です。
環境概要にMacで実行する手順を示し、outputs/mlxのアダプター保存場所を成果物画面で参照できます。
MLXアダプターのRAG直接適用は未実装です。GPUを使うためのMac側エージェントや外部クラウド連接は含みません。

## 安全・バックアップ

Webは127.0.0.1限定・認証なしの単一利用者用です。LAN/インターネットへ公開しないでください。
生成文や文書は外部LLM APIへ送信しません。モデルの初回取得には通信します。
管理DB・学習入力・出典・学習成果物に機密情報が含まれ得ます。公開GitHubへ登録しないでください。
データ・モデル・履歴の削除UIはありません。バックアップはジョブ停止後、コンテナを止めてから実施してください。
