# 専門文書RAGと任意のLoRA追加学習

## 何ができるか

PDF / DOCX / TXT / MDから本文を抽出し、日本語対応埋め込みモデルで意味検索します。
関連する文書抜粋をローカルLLMへ渡して回答し、文書名と原文の位置を表示します。
RAGの文書登録はモデルの学習ではなく、検索用索引の作成です。
確認・修正した回答だけを追加学習候補へ保存できます。保存しても学習は自動実行しません。

構成:

- 文書取込: pypdf / python-docx / UTF-8テキスト
- 埋め込み: intfloat/multilingual-e5-small、CPU、query/passage接頭辞付き
- 保存・意味検索: ローカルSQLiteと正規化ベクトルのコサイン類似度
- 回答: Qwen3 0.6B、CPU、非thinkingモード
- 追加学習: 既存PyTorch LoRAまたはMac側MLX QLoRA（別途実行）
- UI: Streamlit、Mac自身から http://localhost:18083

小型の0.6Bは動作確認向けです。専門的な長文、複雑な数値比較、図の理解を保証しません。
検索だけを行い原文を読む操作もできます。まずは短い公開文書で試してください。

## 1. 起動

Docker Desktopを起動し、LLMonディレクトリで実行します。

```bash
git pull --ff-only
bash scripts/Start-RAG.sh
```

既存利用者も依存関係が増えるため、イメージの再ビルドが必要です。
ブラウザで http://localhost:18083 を開きます。RAGだけの起動にはJupyterトークンは不要です。
通常の`Start-Docker.sh`はJupyterLabとRAGを両方起動します。

GPUは使用せず、MacのDocker内CPUで処理します。MLX学習は別のMac側環境です。
CPU/RAGの同時負荷を避け、学習時は次のようにRAGを停止してください。

```bash
docker compose stop rag
bash scripts/Train-CPU.sh
docker compose up -d rag
```

## 2. 文書を登録

「1. 文書登録」でファイルを選び、「選択した文書を登録」を押します。
1ファイル50MB、PDF500ページ、抽出本文200万文字、索引全体1万チャンクが上限です。
同じファイル内容はSHA-256で重複登録を防ぎます。
同名でも改訂内容が異なるファイルは別文書として登録されます。質問時に版を選択してください。

抽出結果は登録画面で先頭8チャンクまで確認できます。
対応範囲:

| 形式 | 引用位置 | 制限 |
|---|---|---|
| PDF | PDF先頭から数えたページ番号 | 印刷されたページ番号とは異なる場合があります。読み順・表・数式は要確認 |
| DOCX | 本文段落番号、表番号・行番号 | 実ページ番号、画像、脚注、ヘッダー、テキストボックスは未取得 |
| TXT / MD | 原文の行範囲 | UTF-8 / UTF-8 BOM対応。Markdown図などの意味解釈は未対応 |

スキャンPDFのOCRは未実装です。本文がないページは警告し、全ページが空なら登録を拒否します。
一部に画像がある文書は、テキスト部分だけを登録します。表の見出し・結合セル、
図の注記、脚注が回答に必要な場合は、正確に整理したテキストを追加するか原本を確認してください。
暗号化PDFは未対応です。アクセス制限を解除する機能はありません。

## 3. 質問と出典確認

「2. 質問・出典確認」で文書を選び、質問して「検索・回答」を押します。
文書を選ばない場合は登録文書全体を検索します。
「検索結果から回答も生成する」をOFFにすると、LLMを読み込まず関連箇所だけを表示します。
数値・機器型番・版の指定が重要な場合は、その条件を質問に明記してください。

回答の[1]などは、直下の文書名・位置・原文に対応します。
類似度が設定値未満の場合は生成せず、「資料では確認できません」と表示します。
生成回答に存在しない資料番号がある、または出典がない場合も採用せず原文確認を促します。
ただし、これは出典番号の形式検査であり、各主張の意味的な正しさは保証しません。
意味検索の類似度も正答率や確率ではありません。

`config/rag.json`の主な設定:

| 設定 | 初期値 | 意味 |
|---|---:|---|
| chunk_chars | 600 | 文書断片の文字数上限。埋め込み450トークンを超える場合はさらに分割 |
| chunk_overlap | 80 | 隣接断片の重複文字数。トークン分割時は重複幅を調整 |
| top_k | 4 | 質問に対して取得する断片数 |
| min_similarity | 0.75 | 回答に渡すコサイン類似度の基準。未校正の開始値 |
| context_tokens | 1800 | 回答モデルへ渡す抜粋のトークン予算 |
| max_new_tokens | 256 | 回答生成の最大トークン数 |
| adapter_run | 空 | 同じベースモデルのPyTorch LoRA runディレクトリ |

実際の質問・正しい引用箇所で検索品質を確認し、閾値を調整します。
高すぎると回答しない例が増え、低すぎると無関係な抜粋が増えます。
閾値を下げるだけで回答品質が上がるわけではありません。
チャンク設定・埋め込みモデルを変える場合は新しいDBパスを指定して文書を再登録します。
異なる埋め込みモデル/取得revision/次元が混在する索引は拒否します。
モデル名やadapter_runを変更した後は`docker compose restart rag`で再起動し、旧モデルのメモリを解放します。
新しい索引パスも必ず`data/private/`配下を使用してください。

## 4. 必要になったらLoRAを追加

1. 参考資料付きの回答について「3. LoRA用データ」を開きます。
2. 回答を原本と照合し、専門用語、数値、条件、出典を修正します。
3. チェックを入れ、「確認済みの質問・回答を保存」を押します。
4. 「参考資料付き学習候補をJSONLでダウンロード」を押します。

ダウンロードには文書抜粋・出典情報が含まれます。外部共有・公開GitHub登録をしないでください。
このファイルはRAGの答え方を学習する候補です。文書を完全に暗記させるものではありません。
学習しない場合も、RAGだけで文書参照を継続できます。

### 分割とCPU学習

学習候補をそのまま全件学習せず、元文書単位でtrain / valid / testへ分けます。
同じ原文やその言い換えが評価側に入ると、実力以上の評価になります。
`source_metadata`は残してください。バリデーターは同じdocument_idが分割をまたぐ場合も拒否します。
元文書が1つしかない場合は、独立した評価文書を用意するか、まだLoRAを行わずRAGを評価してください。
アプリは自動分割を行いません。

```text
data/private/lora-rag/train.jsonl
data/private/lora-rag/valid.jsonl
data/private/lora-rag/test.jsonl
```

各ファイルにはダウンロードした候補の該当行をUTF-8で保存します。
RAG用の参考資料付きプロンプトは長くなるため、`config/cpu-rag.json`は系列長2048を初期値にしています。
2048でも超える行はエラーになります。原文の条件を損なわないよう参考資料・回答を短くしてください。
長い系列のCPU学習は遅く、実機メモリは未測定です。まず短い数件で試してください。

```bash
docker compose stop rag
bash scripts/Train-CPU.sh --config config/cpu-rag.json --data data/private/lora-rag
```

学習完了後、`config/rag.json`の`adapter_run`へ実際のrunパスを指定します。

```json
"adapter_run": "outputs/cpu/実際の日時-PID"
```

```bash
docker compose up -d rag
docker compose restart rag
```

学習前後を同じ未使用質問と同じ文書で比較し、出典に沿うか、従来の能力が落ちていないか確認します。
モデルの学習は必要な場合だけです。最新版の知識・数値は引き続きRAGの原文から取得します。

### MLXで学習する場合

同じJSONL形式を使えますが、`Train-MLX.sh`の初期ベースは4Bであり、
Docker RAGの初期ベース0.6Bとは異なります。MLXアダプターをこのRAGへ直接適用する機能はありません。
適用にはベースモデルを揃え、MLXの推論連接または重みの統合・変換機能を別途追加する必要があります。
今回の直接連接はPyTorch CPU LoRAだけです。

## 保存とオフライン運用

文書の抽出本文・ベクトル・確認済み回答は`data/private/rag/index.sqlite3`へ保存します。
アップロード原本をアプリがファイル保存する機能はありません。原本は利用者が保管してください。
登録日時はSQLiteのUTC時刻です。元ファイルのハッシュを文書IDとし、出典の同一性を保ちます。
DBのバックアップはRAGを停止してからファイルをコピーしてください。
文書の削除・差し替えUIは今回未実装です。別DBで再登録すると旧版を残したまま索引を作り直せます。

モデル取得時はHugging Faceへ通信します。文書本文を外部LLM APIへ送る処理はありません。
初回に必要モデルを取得した後、厳密なオフライン運用ではragサービスのenvironmentへ
`HF_HUB_OFFLINE: "1"`と`TRANSFORMERS_OFFLINE: "1"`を設定し、
ネットワーク制御も利用してください。キャッシュがない状態では起動・推論に失敗します。

接続先は127.0.0.1限定で、RAGは認証なしの単一利用者向けです。LANやインターネットへ公開しないでください。
ホストの別アプリ・同一利用者からのアクセスを隔離するものではありません。
文書中の命令を無視するプロンプトを使用しますが、プロンプトインジェクションの完全防止ではありません。
プログラム実行、ツール呼出し、外部送信機能はLLMに与えていません。

## 検証範囲

文書抽出、スキャン検出、出典保持、重複登録、ベクトル正規化、モデル不一致検出、文脈予算、
引用番号、確認済みデータのJSONL出力、学習評価への原文漏洩をユニットテストで確認しています。
Dockerビルド・ARM64依存関係の解決・実モデル検索/生成・Streamlitのブラウザ画面は未検証です。
実機確認では登録→検索のみ→回答生成→原文照合→確認済み保存の順で試してください。
